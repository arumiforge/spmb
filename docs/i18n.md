# Website languages (i18n)

The public website is available in **Indonesian** (default), **English** and **Arabic** (D-109).
The staff dashboard, the sign-in page and the PDFs (registration card, attendance sheet) are always
Indonesian; data that applicants or staff type stays as typed.

| Language | Address | `<html>` | Notes |
| --- | --- | --- | --- |
| Indonesian (`id`) | `/`, `/jadwal`, … | `lang="id" dir="ltr"` | default, `x-default` in hreflang |
| English (`en`) | `/en/`, `/en/jadwal`, … | `lang="en" dir="ltr"` | |
| Arabic (`ar`) | `/ar/`, `/ar/jadwal`, … | `lang="ar" dir="rtl"` | right to left, Noto Sans Arabic, Western digits |

Slugs stay Indonesian in every language (`/en/cek-status`, not `/en/check-status`).

## How a request gets its language

1. `Config\Services::incomingrequest()` looks at the route path before routing. A leading `en/` or `ar/`
   is taken off: `/en/jadwal` is routed as `jadwal`, and the request locale becomes `en`
   (`App\Libraries\Locales::apply()`, which also sets the PHP intl default; for Arabic
   `ar@numbers=latn` so `Time::toDateString()` keeps Western digits).
   The prefix stays in the request URI through SiteURI's index-page slot, so `current_url()`,
   `previous_url()` and `redirect()->back()` stay in the language.
2. Routes are registered once; `uri_string()` and `$request->getPath()` are the path without prefix.
3. `App\Filters\WebsiteLanguage` (alias `bahasa`) is a **required** filter, so it also runs before
   routing and on 404 pages:
   - a prefix on a staff or file address (`Locales::STAFF_PATHS`: `admin`, `masuk`, `keluar`,
     `verifikasi`, …; `Locales::FILE_PATHS`: `aset`, `build`, `assets`, `berkas/contoh`,
     `popup/gambar`, `popup/lampiran`) redirects (301) to the address without it;
   - a language the school switched off redirects (302) to the same page in Indonesian;
   - after the response it remembers the language in the cookie `spmb_bahasa` (see below).
4. `$negotiateLocale` stays `false`: the language comes from the address, never from the browser.

`Config\App::$supportedLocales` is `['id', 'en', 'ar']`.

## Links

`app/Helpers/url_helper.php` extends the framework helper: `site_url()` adds the prefix of the current
page (`Locales::prefixPath()`), so `site_url('jadwal')`, `url_to()`, `redirect()->to()`,
`redirect()->route()` and `form_open()` stay in the language. Staff and file addresses, full URLs and
`base_url()` never get a prefix. Built assets use `asset_url()` (`base_url('build/…')`), brand images
`aset/…`; both stay unprefixed. Markdown guide links such as `[Daftar](/daftar)` are rewritten through
`site_url()` by `GuideBuilder`.

Nginx (`docker/nginx/spmb.conf`) needs no change: `/en/…` and `/ar/…` are not files, so `location /`
hands them to `index.php`; `/build/` and `/assets/` are only served without a prefix.

## Switcher, hreflang and the remembered language

- `partials/bahasa_pilih` prints "ID · EN · العربية" in the top bar (from `md`), the drawer and the footer.
  Each link opens the same page (path and query) in that language (`locale_url()`); it is hidden when only
  Indonesian is on.
- `partials/head` (public pages only, `alternates => true`) prints `<link rel="alternate" hreflang>` for
  every language that is on plus `x-default` (Indonesian), and `og:locale` / `og:locale:alternate`.
- Cookie `spmb_bahasa` (1 year, `Lax`, HTTP only) holds the last language the visitor chose: it is set
  when a page is viewed in English or Arabic, or when the visitor moves between pages of the site (e.g.
  presses "ID"). A visitor who arrives from outside (bookmark, search engine, typed address) on an
  Indonesian address while the cookie says `en`/`ar` sees a small bar (`partials/bahasa_saran`) offering
  that language. **There is no automatic redirect**: search engines and shared links always get the
  language of the address, and nobody gets stuck in a language they cannot read.

## Translation files

- Every public string uses `lang()`. English and Arabic live next to the Indonesian files:
  `app/Language/en/*.php`, `app/Language/ar/*.php` and `app/Modules/<M>/Language/{en,ar}/*.php`.
- `App\Libraries\Language` (the `language` service) falls back per key: locale → Indonesian →
  English → the key. So en/ar files only hold public strings; a staff string or a forgotten key shows the
  Indonesian text. A partly translated list (e.g. `App.altStates`) is merged with the Indonesian list.
  **Nested lists that are read item by item** (e.g. `App.navShort.cek-status`) must be complete in the
  language file, otherwise the missing item falls back to Indonesian.
- The instance follows the current request's locale (one shared instance serves every request); `lang($key,
  [], 'en')` picks a language for one line. Numbers in messages use Western digits in Arabic.
- Framework messages (validation) come from `codeigniter4/translations` (`id`, `ar`) and the framework
  (`en`). Field labels and our own validation messages come from the module language files.
- Dates: `tanggal_indo()` follows the page language ("10 January 2027", "10 يناير 2027", times `08:00`
  outside Indonesian); `locale_month_names()` / `locale_day_names()` give the names. The date picker
  (`resources/js/tanggal.js`) reads `<html lang>` and mirrors its arrow keys on rtl pages.
- PDFs stay Indonesian: wrap code that renders one in `Locales::withLocale('id', fn () => …)` (see
  `Kartu\Controllers\Unduh`).

### Adding a public string

1. Add the key to the Indonesian file (`Language/id/<File>.php`), written per the `spmb-copy` skill.
2. Add the English and Arabic values to `Language/en/<File>.php` and `Language/ar/<File>.php`
   (create them when missing, same file name). See the EN/AR section of the `spmb-copy` skill.
3. Use `lang('<File>.<key>')` in the view. Staff-only strings need only the Indonesian value.

### Guides

`/panduan/calon-murid` is built from each module's `Guide/calon-murid.md`. A translation next to it
(`calon-murid.en.md`, `calon-murid.ar.md`; also for files in `Guide/<audience>/`) is used on English and
Arabic pages; without one the Indonesian file shows. Staff guides are Indonesian only.

## Texts the school types

Optional English and Arabic versions, empty = the Indonesian text shows:

| Text | Stored in | Edited on |
| --- | --- | --- |
| Slogan (tagline), motto, address, footer text | settings `School.<key>_en`, `School.<key>_ar` | Identitas Sekolah |
| Questions and answers (topic, question, answer) | `site_questions.<col>_en/_ar` | Website → Tanya jawab |
| Short news | `site_news.text_en/_ar` | Website → Berita singkat |
| Popup title, text, button label | settings `Situs.popupTitle_en`, … | Website → Popup beranda |
| Footer link labels | `label_en`, `label_ar` in the `Situs.footerLinks` JSON | Website → Tautan bawah website |
| Document type name, description, example-link text | `document_types.<col>_en/_ar` | Berkas Wajib |
| Wave name and description | `waves.<col>_en/_ar` | Gelombang Pendaftaran |

- Read them with `localized($row, 'name')` or `setting_localized('School.motto')`
  (`app/Helpers/locale_helper.php`, `Locales::field()` / `Locales::setting()`).
- The built-in default slogan ("Sistem Penerimaan Murid Baru (SPMB)") and the default footer links are
  translated by the language files while the school keeps them unchanged.
- Admin forms show the fields in the fold "Terjemahan (tidak wajib)" (`partials/terjemahan`), only for
  languages that are on; `App\Libraries\TranslationInput::read()` reads and validates them and never
  touches the saved text of a switched-off language. The audit log labels them "<field> (English)" /
  "<field> (Arab)" (`AuditPresenter::fieldLabel()`).
- In views, wrap a translatable school text in `<bdi>` (or `dir="auto"` on a block of Markdown) so an
  Indonesian fallback reads correctly inside an Arabic page.

## Switching a language off

Identitas Sekolah → **Bahasa website**: `School.languageEn`, `School.languageAr` (default on). When off,
the prefix redirects to Indonesian, the switcher and hreflang leave the language out and the admin forms
hide its translation fields (the saved texts are kept).

## Right to left (Arabic)

- Views use logical Tailwind utilities (`ms-`, `me-`, `ps-`, `pe-`, `start-`, `end-`, `text-start`) and
  `rtl:` variants; `icon()` adds `rtl:-scale-x-100` to icons that point a way (arrows, chevrons,
  log-in/out), so do not add a second flip.
- The drawer opens from the left; the bottom bar, stepper, timelines and ticker follow `dir`.
- Components positioned or shaded from one side are mirrored at the end of `resources/css/komponen.css`
  (bottom bar centre button, stepper check mark, pattern fades, hero slide mask, timeline gradient).
- Phone numbers are wrapped in `dir="ltr"` so their digit groups keep their order.
- Font: Noto Sans Arabic (SIL OFL 1.1) from `@fontsource/noto-sans-arabic`, copied to
  `public/build/fonts/` by `scripts/fonts.mjs` (`npm run build`). Browsers download it only on Arabic
  pages (the `@font-face` rules have an Arabic `unicode-range`), where the regular weight is preloaded.
